# 1. 12운성 · 공망

사주 앱의 "전문성 증명" 요소입니다. 계산이 단순해 비용이 거의 들지 않는 반면,
화면에 있으면 "제대로 만든 앱"이라는 인상을 크게 높입니다.

## 1-1. 12운성 (十二運星)

일간(나)이 각 지지에서 어떤 생애 단계에 있는지를 보는 개념입니다.
사람의 일생에 빗대어 열두 단계로 나눕니다.

### 단계 순서

| # | 이름 | 한자 | 뜻 | 한 줄 해설 |
|---|---|---|---|---|
| 0 | 장생 | 長生 | 태어남 | 새로 시작하는 힘. 순수하고 의욕적입니다. |
| 1 | 목욕 | 沐浴 | 씻김 | 다듬어지는 시기. 변덕과 멋 부림이 함께합니다. |
| 2 | 관대 | 冠帶 | 갓을 씀 | 사회로 나서는 단계. 자신감이 넘칩니다. |
| 3 | 건록 | 建祿 | 녹을 받음 | 제 몫을 하는 전성기의 초입. 실속이 있습니다. |
| 4 | 제왕 | 帝旺 | 가장 왕성함 | 힘이 최고조. 주도권을 쥐지만 과신을 조심합니다. |
| 5 | 쇠 | 衰 | 기울기 시작 | 노련해지는 대신 기세는 한풀 꺾입니다. |
| 6 | 병 | 病 | 병듦 | 예민하고 섬세해집니다. 남의 아픔을 잘 압니다. |
| 7 | 사 | 死 | 죽음 | 활동은 줄고 사고는 깊어집니다. 학문·연구에 맞습니다. |
| 8 | 묘 | 墓 | 무덤 | 갈무리하고 저장합니다. 수집·관리에 강합니다. |
| 9 | 절 | 絶 | 끊김 | 단절과 새 출발 사이. 변화가 잦습니다. |
| 10 | 태 | 胎 | 잉태 | 아직 형태가 없는 가능성. 상상력이 풍부합니다. |
| 11 | 양 | 養 | 길러짐 | 보살핌 속에 자랍니다. 온순하고 사교적입니다. |

### 계산법

일간마다 **장생(0단계)이 시작되는 지지**가 정해져 있고,
**양간(甲丙戊庚壬)은 순행**, **음간(乙丁己辛癸)은 역행**합니다.

| 일간 | 장생 지지 | 방향 |
|---|---|---|
| 갑(0) | 해(11) | 순행 |
| 을(1) | 오(6) | 역행 |
| 병(2) | 인(2) | 순행 |
| 정(3) | 유(9) | 역행 |
| 무(4) | 인(2) | 순행 |
| 기(5) | 유(9) | 역행 |
| 경(6) | 사(5) | 순행 |
| 신(7) | 자(0) | 역행 |
| 임(8) | 신(8) | 순행 |
| 계(9) | 묘(3) | 역행 |

```
LIFE_START = [11, 6, 2, 9, 2, 9, 5, 0, 8, 3];   // 일간 index → 장생 지지

stage(dayStem, branch):
    dir  = (dayStem % 2 === 0) ? 1 : -1          // 짝수 index = 양간
    diff = (branch - LIFE_START[dayStem]) * dir
    return ((diff % 12) + 12) % 12               // 0=장생 … 11=양
```

### 검증용 기대값

| 일간 | 지지 | 기대 단계 |
|---|---|---|
| 갑(0) | 해(11) | 장생(0) |
| 갑(0) | 자(0) | 목욕(1) |
| 갑(0) | 인(2) | 건록(3) |
| 갑(0) | 묘(3) | 제왕(4) |
| 을(1) | 오(6) | 장생(0) |
| 을(1) | 사(5) | 목욕(1) |
| 병(2) | 인(2) | 장생(0) |
| 신(7) | 자(0) | 장생(0) |
| 신(7) | 해(11) | 목욕(1) |

> 음간 역행이 헷갈리기 쉬우니 `을`과 `신` 케이스를 반드시 테스트에 넣으세요.

## 1-2. 공망 (空亡)

60갑자를 10개씩 여섯 개의 순(旬)으로 나누면, 각 순마다 짝을 찾지 못한
지지 두 개가 남습니다. 이것이 공망입니다. 보통 **일주 기준**으로 봅니다.

"비어 있다"는 뜻으로, 그 자리에 해당하는 인연이나 재물이 손에 잘 잡히지 않는다고 봅니다.
다만 나쁘게만 보지 않고, 종교·학문·예술처럼 형체 없는 분야에서는 오히려 좋게 봅니다.

| 순(旬) | 60갑자 index | 공망 지지 |
|---|---|---|
| 갑자순 | 0~9 | 술(10), 해(11) |
| 갑술순 | 10~19 | 신(8), 유(9) |
| 갑신순 | 20~29 | 오(6), 미(7) |
| 갑오순 | 30~39 | 진(4), 사(5) |
| 갑진순 | 40~49 | 인(2), 묘(3) |
| 갑인순 | 50~59 | 자(0), 축(1) |

```
voidBranches(ganzhiIndex):
    xunStart    = ganzhiIndex - (ganzhiIndex % 10)
    startBranch = xunStart % 12
    return [ (startBranch + 10) % 12, (startBranch + 11) % 12 ]
```

### 검증용 기대값

- `voidBranches(0)`  (갑자일) → 술·해
- `voidBranches(10)` (갑술일) → 신·유
- `voidBranches(59)` (계해일) → 자·축
- 어떤 index를 넣어도 두 지지는 항상 인접하고, 그 순의 어떤 간지에도 등장하지 않아야 함

## 1-3. UI 배치

**내 사주 탭**, 신살 카드 바로 아래에 새 카드를 둡니다.

```

 ┌────┬────┬────┬────┐
 │ 시주│ 일주│ 월주│ 년주│
 │  절 │ 건록│ 제왕│  묘 │
 └────┴────┴────┴────┘
 월주가 제왕 — 사회 활동에서 힘이 가장 강하게 드러납니다.

🕳️ 공망 — 술(戌) · 해(亥)
 내 사주에서 술·해 자리는 비어 있습니다. …
```

- 용어 사전에 `12운성`, `공망`, `장생`, `제왕`, `건록` 추가

## 1-4. 과금

**무료**로 두는 것을 권합니다. 심층 리포트(20냥)에 이미 십신·직업·연애가 들어 있어
유료 항목을 더 늘리면 무료 화면이 빈약해집니다. 12운성·공망은 "이 앱 진짜네"를
느끼게 하는 신뢰 장치로 쓰는 편이 결제 전환에 더 유리합니다.

## 1-5. 작업 순서

1. `js/saju.js`에 `lifeStage(dayStem, branch)`, `voidBranches(ganzhiIndex)` 추가 후 export
2. `computeSaju` 반환값에 `lifeStages: {year, month, day, hour}`, `voids: [b1, b2]`,
   `voidPillars: ['월주', …]` 추가
3. `js/data.js`에 `LIFE_STAGE_DESC`(12개), `VOID_DESC` 추가
4. `tests/test.js`에 위 §1-1·§1-2 기대값 테스트 추가 (음간 역행 케이스 필수)
5. `js/app.js` `renderSaju()`에 카드 두 개 추가
6. 용어 사전 항목 추가

예상 규모: 엔진 60줄, 콘텐츠 80줄, UI 50줄, 테스트 20건.

# 2. 푸시 알림

## 2-1. 먼저 알아야 할 제약

**현재 구조(GitHub Pages 정적 호스팅)만으로는 진짜 푸시 알림을 보낼 수 없습니다.**
이건 구현 난이도의 문제가 아니라 구조의 문제라, 먼저 결정해야 할 사항이 있습니다.

| 방식 | 가능 여부 | 설명 |
|---|---|---|
| Web Push (표준) | **백엔드 필요** | 구독 정보를 저장하고 VAPID 키로 발송할 서버가 있어야 합니다. 정적 호스팅만으로는 불가능합니다. |
| Notification Triggers API | ❌ | 예약 발송용 표준안이었으나 실제로 널리 출시되지 않았습니다. 의존하면 안 됩니다. |
| 페이지가 열려 있을 때 로컬 알림 | ⚠️ | 앱이 떠 있어야만 동작해 "매일 아침 알림"에는 쓸모가 없습니다. |
| 홈 화면 추가(PWA) + 배지 | ⚠️ | 알림은 아니지만 재방문 유도에 일부 도움이 됩니다. |

### iOS 주의사항

Safari는 16.4부터 Web Push를 지원하지만, **홈 화면에 추가한 PWA에서만** 동작합니다.
사파리 탭에서 그냥 보는 상태로는 알림 구독이 불가능합니다.
따라서 iOS 사용자에게는 "홈 화면에 추가" 안내 단계가 반드시 필요합니다.

## 2-2. 권장 경로

### 1단계 — PWA 기반 마련 (백엔드 없이 가능)

- `manifest.json` 추가: 앱 이름, 테마 색(`#12101f`), `display: standalone`, 아이콘
  - **아이콘 파일이 필요합니다** (192·512px PNG). 🏪 이모지를 렌더링해 만들거나 별도 제작
- `service-worker.js` 추가: 지금은 오프라인 캐시 용도로만. **캐시 전략은 network-first**로 잡으세요.
  cache-first로 하면 배포해도 사용자에게 옛 버전이 계속 보이는 문제가 생깁니다.
- iOS/Android용 "홈 화면에 추가" 안내 UI

이 단계만으로도 앱처럼 실행되고, 이후 푸시의 전제 조건이 갖춰집니다.

### 2단계 — Web Push (백엔드 필요)

최소 구성:

```
[브라우저]  service worker 등록 → 알림 권한 요청 → PushSubscription 획득
              ↓ 구독 정보 전송
[백엔드]    구독 저장 (사용자별 알림 시각, 시간대 포함)
              ↓ 매일 정해진 시각에
            web-push 라이브러리로 VAPID 서명 발송
              ↓
[브라우저]  service worker의 push 이벤트 → showNotification
```

백엔드 후보(무료 티어로 충분한 규모):

| 후보 | 장점 | 단점 |
|---|---|---|
| Cloudflare Workers + KV + Cron Triggers | 무료 한도 넉넉, 크론 내장 | KV 정합성이 느슨함 |
| Supabase (Postgres + Edge Functions + pg_cron) | DB를 함께 씀 | 무료 인스턴스 휴면 |
| Firebase Cloud Messaging | 모바일 확장 쉬움 | 구글 종속, iOS 설정 번거로움 |

**추천: Cloudflare Workers.** 정적 사이트를 그대로 두고 알림만 얹기에 가장 가볍고,
크론 트리거가 내장이라 "매일 오전 8시 발송"을 별도 스케줄러 없이 처리할 수 있습니다.

## 2-3. 알림 내용 설계

매일 같은 문구면 금방 무시당합니다. 그날의 운세에서 뽑아 쓰세요.

```
🏪 운세 편의점
오늘의 총운 82점 — 「먹을 복과 여유가 함께하는 날」
행운의 색은 초록색이에요. 눌러서 확인해 보세요 →
```

- 점수와 헤드라인을 넣으면 열어 볼 이유가 생깁니다
- **운세 계산은 클라이언트에서만 가능**하다는 점에 주의하세요.
  서버가 사주를 계산하게 하려면 만세력 엔진을 서버로 옮기거나(Node로 그대로 실행 가능),
  가입 시 계산 결과를 백엔드에 저장해 두어야 합니다.
  → `js/saju.js`, `js/fortune.js`는 이미 CommonJS export를 지원하므로 Workers에서 재사용 가능합니다.
- 알림 시각은 사용자가 고르게 하고(기본 오전 8시), 시간대를 함께 저장하세요.

## 2-4. 과금 연계

알림 자체는 무료로 두되, **출석 도장과 묶으면** 재방문 효과가 큽니다.

- 알림을 통해 들어오면 출석 도장 자동 적립
- "알림 켜기" 최초 1회 보상 +10냥
- 7일 연속 출석 시 보너스

## 2-5. 작업 순서

1. 아이콘 제작 (192·512px) → `manifest.json` 추가
2. `service-worker.js` (network-first 캐시) + 등록 코드
3. "홈 화면에 추가" 안내 UI (iOS는 별도 문구)
4. **여기서 백엔드 선택 결정** ← 진행 전 합의 필요
5. Cloudflare Worker: 구독 저장 API, VAPID 키 발급, 크론 발송
6. 클라이언트: 권한 요청 UI, 구독 등록, 알림 시각 설정
7. service worker `push` / `notificationclick` 핸들러
8. 출석 보상 연계

예상 규모: 1~3단계는 반나절, 4~8단계는 백엔드 포함 2~3일.

> ⚠️ 4단계 이후는 서버 비용·개인정보(구독 토큰) 보관 이슈가 생깁니다.
> 개인정보처리방침 문구도 함께 준비해야 합니다.

# 우선순위 제안

1. **12운성·공망** — 비용 대비 신뢰도 상승이 가장 큽니다. 백엔드가 필요 없어 바로 진행 가능합니다.
2. **PWA 1단계** — 아이콘만 준비되면 반나절. 푸시의 전제 조건이기도 합니다.
3. **Web Push 2단계** — 백엔드를 붙일 준비가 됐을 때.
